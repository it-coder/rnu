## rnu 项目通读 + 全面体检（代码审查）

**项目**：`rnu`（Rust Nexus Uploader），单 crate CLI，二进制名 `nexus-upload`。把本地 npm / Maven 包批量上传到 Nexus RM 3.x。约 2450 行 Rust。

**验证结果**
- `cargo check --all-targets`：通过，但 **21 条 clippy warning**（14 dead_code / 3 可自动修 / `&PathBuf` 应为 `&Path` / 8 参数超限 / 连续 `str::replace` / `io::ErrorKind::Other`）。
- `cargo test`：**15 passed, 0 failed, 2 ignored**。
- `make check`（含 `clippy -D warnings`）**当前会失败** —— CLAUDE.md 里"提交前必跑 make check"与现状冲突。

**关键问题清单（按严重度）**
1. **P0 凭据泄露**：`src/nexus/mod.rs` 测试 `test_config()` 硬编码真实环境下发地址 `http://20.21.1.180:18081` / `admin` / `Zyjc@2020`。另有 `test_upload_tarball` 硬编码 `/Users/lih/Downloads/zxing-wasm-1.3.4.tgz` 绝对路径。
2. **P1 scoped 包名被截断**：`PackageScanner::extract_name` 对 `@types/node` 返回 `node`。后果：`--only`/`--exclude` 对 scoped 包完全失效；`--skip-existing` 永远查不到已存在（查的是 `node` 而不是 `@types/node`）；去重 key 变成 `node@version`，不同 scope 同名包会互相覆盖丢失。
3. **P1 Maven classifier 丢失**：`classify_extension` 把 `-sources.jar` / `-javadoc.jar` 一律归为 `"jar"`，上传时只设 `maven2.assetN.extension=jar`，没有 `maven2.assetN.classifier`，sources/javadoc 会被当成主 jar 上传。
4. **P2 进度汇总失真**：`UploadProgress::increment_skipped` 从未被调用，`--skip-existing` 跳过的包不计入统计，最终 summary 的 skipped 恒为 0、Total 只显示过滤后数量。
5. **P2 `utils` 模块几乎全是死代码**：`format_bytes` / `confirm_prompt` / `print_*` / `truncate_string` / `is_valid_url` / `sanitize_package_name` / `SimpleProgress` 全部未使用。
6. **P2 文档不一致**：`Cargo.toml` / `cli.rs` 版本 `0.1.0` vs `PROJECT_SUMMARY.md` 写 `v0.2.0`；`Makefile` package target 复制 `README.md`（大写），仓库实际是 `readme.md`（小写，Linux 上会失败）；`config.example.json` 有 4 个 profile 而 `create_sample_config()` 只生成 2 个。
7. **P3 `.DS_Store` 被 git 追踪**（`.gitignore` 已存在但未忽略）；`docs/` 是空目录。
8. **P3 `create_and_upload_tarball`**：`fs::remove_file(&tarball_path)?` 在返回前执行，清理失败会用 IO 错误覆盖真实上传错误。
9. **P3 `run()`/`run_maven()`**：`self.config` 字段带 `#[allow(dead_code)]`，注释有重复（两个 "// 5."）。
10. `include_dev` / `PackageJson.dependencies` 完全未使用（`_include_dev`）。

**未提交状态**：`master` 落后于工作区很多 —— `src/nexus.rs` 已删除、`src/nexus/` 与 `src/cli.rs`、`CLAUDE.md`、`AGENTS.md` 未追踪。整体重构（拆模块 + 加 Maven 支持）尚未 commit。

## 追加：`make package` 打包链路的跨平台审查

**实测环境**：macOS（APFS **大小写不敏感**，已验证）、GNU Make、`/bin/sh` 为 bash、本机另有 `/bin/dash`。执行 `make package` 真实成功，产物 `dist/rnu-0.1.0.tar.gz`（1.1 MB），内含 `./nexus-upload ./README.md ./config.example.json ./example_usage.sh`，二进制 `Mach-O 64-bit executable arm64`、2.0 MB。审查后已删除 `dist/`。

**确定会坏的地方**
1. **Linux 上 `make package` 必然失败**：`cp README.md dist/`，而仓库实际文件名是 `readme.md`（`git ls-files` 已确认）。macOS 只因为卷大小写不敏感才侥幸通过；到大小写敏感的文件系统就是 `cp: cannot stat 'README.md'`，make 立即中止，tarball 都生不出来。**最该修的一条。**
2. **`docs` 是死目标**：`docs` 未列入 `.PHONY`，而仓库已有 `docs/` 目录 → `make docs` 实测输出 `make: 'docs' is up to date.`，什么都不做。`.PHONY` 只声明了 8 个目标，另有 **20 个目标未声明**（all / package / check / deps / update / docs / tag / profile / watch / dev-run / install-user / uninstall-user / format-check / init-config / show-config / list-profiles / bench-build / setup-dev / test-dry-run / test-verbose）。`package` 同理有静默 no-op 风险。反向问题：`.PHONY` 里声明的 `run-tests` 根本不存在。
3. **Windows 上打包链断两处**：(a) `make` 非标配，recipe 全是 `mkdir -p`/`cp`/`tar -czf` POSIX 命令，cmd.exe/PowerShell 都没有，必须走 MSYS2/Git Bash/WSL；(b) `cp target/release/nexus-upload dist/` 少了 `.exe`，Windows 上 Cargo 产出 `nexus-upload.exe`，源文件名对不上。同样的 `.exe` 缺失还影响 `init-config` / `show-config` / `list-profiles` / `test-dry-run` / `profile`（都是 `./target/release/nexus-upload`）。
4. **`make tag` 不会同步 clap 版本**：`src/cli.rs:7` 是硬编码 `version = "0.1.0"`（clap 显式 version 会覆盖 `CARGO_PKG_VERSION`），`tag` 只改 `Cargo.toml` → `nexus-upload --version` 永远停在旧版本。另 `sed -i.bak` 会留下 `Cargo.toml.bak` 未清理。
5. **`examples/example_usage.sh` 在 dash 下输出乱码**：`echo -e` 在 dash 里不认 `-e`（dash 的 echo 默认处理反斜杠），实测 `/bin/dash -c 'echo -e "A\tB"'` → `-e A<TAB>B`，即把 `-e` 当字面文本打出来。

**跨平台能力分层**
- 纯 cargo 目标（`build` / `release` / `test` / `format` / `lint` / `check-deps` / `deps` / `update`）：只要装了 make 就能跨平台。
- 依赖 POSIX 工具的目标（`package` / `clean` / `install*` / `uninstall*` / `tag` / `profile` / `watch` / `bench-build` / `init-config` 等）：需要 MSYS2/Git Bash；`install`/`install-user` 的 `sudo`、`chmod`、`/usr/local/bin`、`~/.local/bin` 是 Unix 专属，Windows 无对应。
- `profile` 是全文件唯一做了平台回退的地方（`ldd || otool -L || echo`），但只覆盖 macOS/Linux。

**其他打包质量问题**
- 产物名不含 target triple —— 实测 macOS ARM64 二进制与 Linux 上同名 `rnu-0.1.0.tar.gz`，无法区分；也没有生成校验和文件。
- `package` 只跑 `cargo build --release`、无 `--target`，本质是"宿主平台产物"，谈不上跨平台发布。
- `tar -czf dist/rnu-*.tar.gz -C dist .` 会把归档自身纳入扫描，实测 bsdtar 报 `Can't add archive to itself`（bsdtar/GNU tar 都会自动跳过，结果正确但输出刺眼，跨 tar 实现行为不保证一致）。
- `clean` 里 `cargo clean` 之后又 `rm -rf target/`，冗余。
- `bench-build` 里的 `time` 依赖 shell builtin（Windows make 无），且一个"基准测试"目标内含 `cargo clean` 清空构建缓存，副作用过重。
- **`dist/` 未加入 `.gitignore`**（当前只有 `/target`）→ 打包产物会被误提交。

**修复方向（待用户拍板）**
A. 最小修补：`README.md`→`readme.md`、补 `.PHONY`、引入 `EXE`/`BIN` 变量处理 `.exe`、tarball 名带 target triple。
B. 把打包逻辑挪进 Rust（`cargo xtask` 或 `src/bin/`），彻底摆脱 shell 依赖，Windows 原生可跑。
C. 本地 Makefile 保持 macOS/Linux 专用，跨平台发布交给 CI matrix（`cargo build --target <triple>` + 上传 artifact）。
